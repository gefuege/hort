Hort – secrets for you and your agents.

One encrypted vault for your API keys, tokens and passwords. You use it. Your coding agents use it. Your keys never leave your devices.

// agents

Your agent asks. You answer. It never sees the secret.

Agents need credentials. Today you paste them into the chat, the agent forgets, and next session it asks again. Hort gives your agents one place to look, and one polite way to ask for what's missing.

[01]

Discover

The agent runs hort list and sees what exists: names, descriptions, environments. No values.

[02]

Read

hort get <name> prints just the value on stdout. Ready for $(...) and pipes. Locked vault? Exit code 2, and the agent asks you to unlock.

[03]

Ask for what's missing

The agent requests a secret by name via MCP. You get a link, open hort.pm and type the value there. The agent only learns that the secret now exists.

Read

# What's there?
$ hort list --json

# Use it
$ export STRIPE_KEY=$(hort get stripe-key --env prod)

# Different value per customer
$ hort get tenant-id --env prod --context acme

Fallback built in: env+context → env+* → *+*. Specific wins, the baseline catches the rest.

Ask

agent  › I need the Stripe client ID for this integration.
hort   › Requested "stripe / client_id". Waiting for you on hort.pm …
you    › (open the link, enter the value, done)
agent  › $ hort get stripe client_id

The value goes from your browser into your vault. The chat only ever sees the name.

Using Claude Code? Add the MCP server once with claude mcp add hort -- hort mcp. Then your agent can request a secret by name; you type the value on hort.pm, never into the chat.

// features

Small tool. Sharp edges where they belong.

  • One encrypted vault.AES-256-GCM, key derived with Argon2id. One file on your disk.
  • Built for agents.hort --help teaches an agent the whole interface in one call. Plain values on stdout, errors on stderr, --json when it wants structure.
  • Environments and contexts.One name, many values: dev, prod, per tenant or customer. Lookups fall back to the baseline.
  • History.Every change is a revision. hort history <name> shows what changed and when.
  • Offline first.No telemetry, and reads and writes keep working without a network. Hort works on a plane.
  • Values stay out of your shell history.--value-stdin keeps secrets out of process arguments.
  • Secret Key + passphrase.Unlock with your passphrase plus a device-generated Secret Key. A stolen copy of your vault is useless without both.
  • Passkey unlock in the browser.Unlock hort.pm with a passkey (WebAuthn PRF). No passphrase typing on every visit.
  • Named fields.One secret, several parts: hort get stripe client_id, hort get stripe secret.
  • Encrypted sync, hosted in the EU.Your devices sync through hort.pm, hosted on Cloudflare in the EU, or through a server you host yourself. The server stores ciphertext and never sees a key. Sync runs when you use Hort.
  • hort.pm web app.Read, copy and set secrets in the browser, on any device you trust.
  • Agents ask, you answer.Agents request missing secrets via MCP. You enter them on hort.pm; the agent gets the name, not the value.

// security

Where your secrets live, honestly.

A secret manager earns trust by saying what it protects and what it doesn't. Here's ours.

What Hort protects

  • Keys and plaintext exist only on your devices, and in your browser while hort.pm is unlocked.
  • The vault is encrypted with AES-256-GCM. Tampering is detected.
  • The sync server stores ciphertext only. It cannot read your secrets.
  • Agents get values through the CLI on your machine. With the request flow, they never get values you type for them.

What Hort does not protect against

  • Someone who controls your machine. Root or malware on an unlocked device can read what you can read. That's true for every local secret manager.
  • Whoever controls the hort.pm deployment. The web app is JavaScript served by hort.pm. Whoever controls that deployment could ship code that reads secrets after you unlock in the browser. We reduce the risk: strict Content Security Policy, no third-party scripts, open source code you can check. If you don't want this risk at all, use only the CLI. Or run the backend yourself.
  • Losing both Secret Key and passphrase. Then your data is gone. Nobody can reset it, including us. Print your Emergency Kit and keep it somewhere safe.

Today, specifically: The sync server holds only encrypted vault data. Opening it takes your Secret Key and your passphrase, and neither ever leaves your devices.

// install

Install in one line.

macOS (Homebrew)

brew install sebastian-breitzke/tap/hort && hort init

npm (any OS)

npm install -g @s16e/hort && hort init

Windows (Scoop)

scoop bucket add sebastian-breitzke https://github.com/sebastian-breitzke/scoop-bucket
scoop install hort
hort init

Linux and Windows binaries

GitHub Releases

After install

printf '%s' "$KEY" | hort set openai-key --value-stdin --description "OpenAI API key"
hort get openai-key

Set a passphrase during hort init. That's it. Then tell your agent to run hort --help.

Why "Hort"?

"Hort" is German for a safe place, and for a treasure hoard, like the Nibelungenhort. The logo is a key in a nest: your secrets, kept safe, close to home.
